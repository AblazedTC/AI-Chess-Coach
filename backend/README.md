# Chess Coach backend

Python 3.13, FastAPI, python-chess, and uv. From the repository root:

```powershell
uv --directory backend sync --locked
uv --directory backend run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

The defaults (`CHESSCOM_MODE=demo ENGINE_MODE=demo LLM_PROVIDER=deterministic`)
make **no network calls**. `/api/demo` returns a synthetic, reproducible 26-ply
game. Interactive API documentation is at `http://127.0.0.1:8000/docs`.
`backend/openapi.json` is generated by:

```powershell
uv --directory backend run python scripts\export_openapi.py
```

## Modes and evidence

* **Demo:** White-minus-Black material only (pawn 100, knight 320, bishop 330,
  rook 500, queen 900). Not a chess engine evaluation. Lines are lexicographically
  selected legal examples, **not recommendations**, and `best_move`, `depth`,
  `classification`, and `loss_cp` are null. Even terminal positions retain
  material-only scores, not invented mate evaluations.
* **Stockfish:** Set `ENGINE_MODE=stockfish` and `STOCKFISH_PATH` to your own
  native executable. No binary is bundled or downloaded. One exclusive UCI
  child process has bounded depth, time, memory, threads and queue waits.
  Cancellation, timeout, shutdown and protocol failures terminate/reap it;
  a later request can start a fresh process. Missing configuration fails startup;
  an unavailable executable yields a sanitized 503 on analysis.
* **Scores:** Always White POV. `kind: "mate"` preserves signed moves-to-mate,
  distinct from centipawns. Positive favors White; negative favors Black;
  mate 0 denotes an already-mated board. Move classifications concern the move
  **leading into** the selected ply, using adjacent bounded searches. CP loss
  is null when either score is mate; these are estimates, not proofs.
* **Coach:** Explains move-specific fundamentals: loose pieces and legal
  recaptures, central pawn support, development, center control, and castling.
  It compares the played move with Stockfish's pre-move alternative and the
  opponent's continuation, rather than treating an evaluation change as a lesson.
  Evidence cites `game_id:ply:position_key`, including the previous position when
  comparing moves. Geometric defenders are not assumed to be legal recaptures,
  and an unrecapturable capture does not prove a sacrifice is unsound.
  Optional Anthropic mode
  requires explicit `LLM_PROVIDER=anthropic` and `ANTHROPIC_API_KEY` configuration
  (never commit `.env`). This mode sends the question/history and bounded
  verified position facts to the official Messages API and may incur charges.
  The model writes short explanations and one practical takeaway, citing supplied
  board/engine evidence for each paragraph. Unknown citations, unsupported moves,
  squares, piece placements, tactical motifs, and numerical evaluations are rejected.
  These checks do not prove the model's causal interpretation; it can still be wrong.
  Citations, move legality, and engine-verification flags remain server-owned.
  Unsupported or unavailable output falls back honestly with a warning.
  No model calls are made during testing. API reference:
  https://platform.claude.com/docs/en/api/messages .
* **Insights:** Counts of actual checking moves, captures, castling and
  promotions across unique games, with supporting positions. They do not claim
  engine-confirmed weaknesses or infer player intent.

## Public data, isolation and limits

`CHESSCOM_MODE=live` opts into the public Chess.com API. Usernames are validated,
URLs are fixed/allowlisted, requests are serial with spacing and timeouts,
redirects are disabled, and responses/cache sizes are bounded. Recent games
use at most two monthly archives and return at most 20 standard-chess games.
No authentication credentials or private game fixtures are used.

Import accepts one legal standard PGN, including FEN starts, comments and
variations, up to 250,000 characters, 500 mainline plies and variation depth 16.
Canonical replay strips comments and variations. Its SHA-256 prefix is the
stable game ID; the full FEN SHA-256 prefix is `position_key`. Full FEN includes
move counters; different counters intentionally mean different identities.
Practice replays up to 100 legal UCI moves on an independent board, preserving
the selected game's move history without mutating replay or analysis.

All state is bounded **process-local, in-memory, expiring** storage, not durable
accounts. Defaults: 128 games, 2,048 evaluations, 16 jobs, 2 active jobs,
one-hour TTL. Job totals include initial position (plies + 1). Terminal jobs
are evicted first; active duplicate submissions return the same job. A game
evicted during its job causes an honest failed job; reimport and retry.
Use **one worker** so all requests share state. Restarting loses imports/jobs.
Concurrent HTTP requests are bounded at 32 and bodies at 300,000 bytes.
Validation and provider errors are sanitized JSON envelopes with request IDs.

CORS is restricted to explicitly configured localhost/loopback origins;
credentials are disabled. `.env.example` lists configuration. This is a local
application, not a multi-user public service: do not expose it to the internet
without authentication, authorization and deployment-level rate limits.

## Validation

```powershell
uv --directory backend sync --locked
uv --directory backend run ruff check .
uv --directory backend run ruff format --check .
uv --directory backend run mypy app
uv --directory backend run pytest
# Optional actual native-engine integration tests:
$env:STOCKFISH_PATH = 'C:\tools\stockfish.exe'
uv --directory backend run pytest -m stockfish
```

The default tests fake all external HTTP/UCI behavior. Real-engine tests skip
only when `STOCKFISH_PATH` is unset.
